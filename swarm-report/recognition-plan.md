# Plan: точное распознавание предметов + лого хакатона по тапу   (slug: recognition)

## TL;DR

**Точность.** Gemini сначала называет предмет (`seen`) и свою уверенность (`sure: high|low`): эти поля стоят в схеме раньше `text`, через `propertyOrdering`. При `sure=low` кот говорит реплику-догадку, а не выдаёт предмет за факт.

**Лого «Арены героев».** Узнаётся по тапу. К запросу прикладывается эталон лого с сервера (`api/_logo.js`), промпт описывает допуски и негативы. Сервер ставит `hero=true` только при `logo && sure=high`.

**Тап по человеку в футболке с лого.** Уходит вырезка торса с закрашенными лицами, но только если её пропустил локальный гейт контраста. Это меняет решение о приватности, см. D1.

**Заглушка для анимации.** Фронт ставит `body.is-hero` и шлёт событие `cat:hero`, к ним коллега цепляет анимацию маски. `cat.js` не трогаем.

**Что нашлось в коде:**
- Подсказка «Детектор думает…» на деле не работает: фронт всегда шлёт `label: 'unknown'`.
- В схеме нет `propertyOrdering`, поэтому Gemini пишет поля по алфавиту: `mood` раньше `text`, а предмет не называется вообще.
- Вырезка 416 px из кадра 960×540 — это около 77% высоты кадра, в неё попадает много соседних предметов. JPEG 0.8.
- Температуру 1.0 не трогаем: так рекомендует Google для Gemini 3.
- Базовая точность не измерена.

## Acceptance criteria

**Тесты.** `npm test` зелёный. Новые тесты покрывают схему, разбор ответа, `hero`, `torso`, гейт и `pickTarget`.

**Предметы (eval, 25+ вырезок):**
- правильный `seen` или честная догадка в ≥ 85% случаев;
- уверенно неверных ответов ≤ 2;
- догадок ≤ 30%;
- результат лучше базового прогона.

Реплика при `sure=low` звучит как догадка или вопрос.

**Лого:**
- позитивы (≥ 10: ровное, помятое, под 45°, половина маски, распечатка, экран): `hero` в ≥ 8 из 10;
- негативы (≥ 10: живая кошка, кошачьи уши, хэллоуинская летучая мышь, символ Бэтмена в овале, маска с ртом, однотонная футболка, другой белый принт, кружка): `hero` в 0 случаях.

**Задержка.** p90 в eval ≤ 5 с, на iPhone обычно ≤ 3.5 с. Таймауты 8 с и 9.5 с не меняются.

**Сбой Gemini.** Кот говорит фразу из `phrases.json`, `hero` не ставится.

**Приватность:**
- тап по лицу: картинка не уходит, в теле запроса `{kind, emotion}`;
- торс на однотонной футболке: гейт не пропустил, `torso` не уходит;
- торс с лого: уходит `torso` с закрашенными лицами, кот надевает «маску»;
- удержание по торсу (обида): `torso` не уходит никогда.

**Hero-хук.** При `hero` на `body` ставится класс `is-hero`, на `document` приходит `cat:hero` с `detail.text`. Следующий тап снимает класс. Поза `happy`.

**Окно «Как это»** честно сообщает, что при тапе по одежде уходит кусок кадра с закрашенными лицами.

**Живой smoke** (`npm run dev`) для object, person и person+torso: ответ 200, Gemini принимает `propertyOrdering`.

## Plan

0. **Решения человека** D1–D3 (Blockers). Без «да» по D1 делаем шаги 1–4 и путь лого только через object, без торса.

1. **[backend] Скрипт оценки.** `scripts/eval-recognition.mjs`, `package.json` `eval`, `.gitignore` `eval/crops/`.
   - Человек собирает вырезки через `?debug`: 25+ предметов и 20 лого/не-лого.
   - Прогон базы на текущем `ask.js`: около 45 запросов, это 3% дневной квоты.

2. **[backend] `api/_logo.js`.** Эталон 320 px, q85, base64 около 15–20 КБ, импорт через ESM. Тест: строка начинается с `/9j/` и короче 40 000 символов.

3. **[backend] `api/ask.js`.**
   - Схемы с `propertyOrdering`:
     - OBJECT: `seen`, `sure`, `logo`, `text`, `mood`;
     - TORSO: `logo`, `sure`, `text`, `mood`;
     - PERSON: `text`, `mood`.
   - `SYSTEM_PROMPT`: порядок работы (предмет ровно в центре), правило `sure=low`, блок лого с допусками и негативами, правило для торса (ни слова об одежде и теле).
   - `parseAsk`: принимает `torso`; вместе с `grudge` торс отбрасывается.
   - `geminiRequest` собирает части по порядку: подпись, эталон, подпись, вырезка, `userPrompt`.
   - `parseReply`:
     - `hero = logo && sure=high`;
     - при `hero` `mood='happy'`, текст без корня «геро» заменяется на `HERO_LINES`;
     - невалидный `sure` считается `low`;
     - длинный `seen` отбрасывается, ответ не отклоняется.
   - Env `GEMINI_THINKING` (белый список, по умолчанию `low`).

4. **[backend] Живой smoke и eval №2.**
   - p90 > 5 с: `mediaResolution MEDIUM` или эталон 256 px.
   - Есть ложные срабатывания лого: ужесточить негативы.
   - Сравнить thinking `low` и `medium`.

5. **[frontend] Клиентская часть.**

   - `logic/logoGate.js`: `mayHoldLogo` по 32×32. Пропускает, если почти белых пикселей 3–60% и тёмных ≥ 15%.
   - `snapshot.js`: JPEG 0.9, новая `torsoSnapshot` с закраской лиц и гейтом.
   - `logic/askCat.js`: `torso` и `hero`.
   - `main.js`: торс в `respond`, хук `is-hero` и `cat:hero`.
   - `devLog`/`devMode`: в логе `seen`, `sure`, `hero`, вырезка торса в `debugCrop`.
   - `index.html`: текст про одежду.

6. **[frontend, можно вырезать]** A/B-метка места тапа (кольцо) под `?tapmark`.

7. **Ручная проверка на iPhone** по списку:
   - предметы вплотную друг к другу;

## Blockers

**Решено человеком (31.10):**
- **D1 = (b).** Торс с закрашенными лицами уходит только после локального гейта.
- **D2.** Одна заготовленная фраза. При `hero` текст всегда «Маска надета. Арена героев, я с вами!», реплику Gemini не используем.
- **D3.** Футболки чёрные, лого — только белая маска, без квадрата с городом. Пороги гейта настраиваем под это.
- **Eval-скрипта нет.** Шаг 1 вычеркнут: не делаем `scripts/eval-recognition.mjs`, скрипт `eval` в `package.json` и `.gitignore`. Точность проверяет человек руками на iPhone по dev-логу (шаг 7). Живой smoke в шаге 4 остаётся.

1. ~~**D1, приватность торса.**~~ Нужно решение человека.
   - (a) Вырезка торса с закрашенными лицами при любом тапе по торсу.
   - (b) **Рекомендация planner'а:** то же, но только если пропустил локальный гейт.
   - (c) Торс не отправляем вообще. Тогда лого узнаётся только на распечатке, экране и крупном плане.

   Варианты (a) и (b) меняют решение «фото посетителей не отправляем» в `decisions.md`.
2. **D2, фирменная фраза.** Пока заглушки `HERO_LINES` вида «Маска надета. Арена героев, я с вами!».
3. **D3, фото реальной футболки или распечатки.** Нужно, чтобы подобрать пороги гейта и собрать позитивы для eval.
4. **Сбор вырезок для eval (шаг 1)** — ручная работа человека, 45+ кадров. Возможно, сократить.
5. **Владелец `scripts/` и `.gitignore`** в AGENTS.md не указан, planner предполагает backend.
6. **Gemini может ответить 400** на `propertyOrdering` или BOOLEAN. Живой smoke в шаге 4 обязателен до пуша.
7. **Эталон в запросе может путать модель:** реплика об эталоне или `hero` на всё подряд. Есть хотя бы одно ложное срабатывание на негативах — не пушить.
8. **Квота.** 2–3 прогона eval — около 10% дневной квоты, не в день защиты.

## Out of scope

- Анимация и картинка маски, любые правки `cat.js`.
- Автоматический опрос кадра (решено: только по тапу).
- Распознавание лого без Gemini: в офлайне лого не узнаётся.
- Разрешение камеры, модели на устройстве, свой детектор лого.
- Маска на сохранённом фото, звук на hero, выбор между несколькими предметами.
