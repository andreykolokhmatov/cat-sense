# Кошачье чутьё: правила разработки

Облегчённая версия [labs-harness](https://github.com/ayusavin/labs-harness) под проект на 3 дня и 2 человека.
Что это за проект: [`.memory-bank/index.md`](.memory-bank/index.md).

## Цикл

1. `/plan "<фича>"`: агент `planner` читает Memory Bank и пишет план с критериями приёмки в `swarm-report/<slug>-plan.md`.
2. `/build <slug>`: агент, которому принадлежат файлы, делает план и запускает тесты.
3. `/debug "<ошибка>"`: когда что-то сломалось. Сначала воспроизвести, потом минимальный фикс.
4. `/review <slug>`: проверка diff по плану. Запускаем перед демо и деплоем, не на каждую фичу.

План пишем один раз на блок работы, а не на каждую мелочь. Опечатки и правки в одну строку идут без `/plan`.

## Тесты: мягкий гейт

Stop-хук `.claude/hooks/test-gate.mjs` не даёт сказать "готово", если правилась логика, а `npm test` не запускали.

- Гейт работает на `api/**` и `public/js/logic/**`.
- Камера, Canvas, стили и анимация кота гейтом не закрыты. Их проверяем руками на телефоне.
- Пока в `package.json` нет скрипта `test`, гейт спит.

Поэтому чистую логику держим в `public/js/logic/`, без DOM и камеры: правила эмоций, выбор фразы, таблица "хочу/не хочу".

## Договорённости

- **Точность важнее скорости.** Проверяй, прежде чем сказать "готово". Тесты зелёные не значит, что фича работает.
- **Сначала Memory Bank.** `.memory-bank/index.md` главный источник фактов о проекте. Нет факта: скажи об этом, не выдумывай.
- **Спорь вслух.** Запрос неверный, объём раздут, план с дырой: скажи и предложи одну альтернативу.
- **Сиди в своей зоне.** Исполнитель меняет только свой слой. Влияние на другой слой описывает в отчёте.
- **Edit важнее Write.** Правь существующее, новые файлы только по плану.
- **Комментарии только "почему".** Не пересказывай код.
- **Безопасность.** Ключ Gemini только в переменных окружения Vercel и в локальном `.env`, в браузер и git не попадает. Внешний ввод проверяется на границе.
- **Linux и Windows.** Разработка идёт на обеих системах, хостинг Vercel. Команды в `package.json` пишем так, чтобы работали на обеих. Пути через `node:path`. Регистр имён файлов и импортов совпадает точно: на Windows ошибка незаметна, на Linux ломает запуск.
- **Спрашивай перед рискованным:** удаление файлов и веток, force push, удаление зависимостей, всё видимое вне репозитория.
- **Демо важнее фич.** Реплики пишет Gemini, но если он недоступен, кот говорит запасную фразу из `phrases.json`, и сценарий не падает. Новая фича не должна ломать основной сценарий.
- **Коротко.** Отвечай по делу, без воды. Код и коммиты пишутся нормально.
